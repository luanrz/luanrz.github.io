前言 ​

约定 docker run 的参数顺序如下：

  • 运行模式：-d / -it / --rm
  • 容器标识：--name
  • 网络配置：-p / --net
  • 存储挂载：-v
  • 环境变量：-e
  • 资源限制：-m / --cpus
  • 特权与硬件：--device / --cap-add
  • 其它：--stop-timeout

约定 docker-compose.yml 的参数顺序如下：

  • 镜像名：image
  • 容器标识：container_name
  • 网络配置：ports / networks
  • 存储挂载：volumes
  • 环境变量：environment
  • 资源限制：resources
  • 特权与硬件：devices / cap_add
  • 其它：stop_grace_period / restart / depends_on

-d \
--name elasticsearch01 \
-p 127.0.0.1:9200:9200 \
--net elastic \
-v ./elasticsearch/data/:/usr/share/elasticsearch/data/ \
-e discovery.type=single-node \

-e "ELASTIC_PASSWORD=Passw0rd" \

（2）设置ES密码

可选，如果在这里设置了ES密码，上述ELASTIC_PASSWORD=Passw0rd配置将会失效。执行下述命令需要配置xpack.security.enabled=true。

LogStash ​

（1）创建logstash.yml配置文件

shell
cat > ./logstash/config/logstash.yml << EOF
http.host: "0.0.0.0"
xpack.monitoring.elasticsearch.hosts: [ "http://elasticsearch01:9200" ]
xpack.monitoring.elasticsearch.username: "elastic"
xpack.monitoring.elasticsearch.password: "Passw0rd"
EOF

（2）创建logstash.conf配置文件

shell
cat > ./logstash/config/logstash.conf << EOF
input {
  file {
    path => "/var/log/logstash/*.log"
    start_position => "beginning"
    codec => multiline {
      pattern => "[#%&*^]"
      negate => false
      what => "next"
    }
  }
}

output {
  # 输出ES
  elasticsearch {
    hosts => ["http://elasticsearch01:9200"]
    index => "log-%{+YYYY.MM.dd}"
    user => "elastic"
    password => "Passw0rd"
  }

  # 输出到控制台
  stdout {
    codec => rubydebug
  }  
}
EOF

（3）启动LogStash容器

shell
docker run \
-d \
--name logstash01 \
--net elastic \
-v ./logstash/config/logstash.yml:/usr/share/logstash/config/logstash.yml \
-v ./logstash/config/logstash.conf:/usr/share/logstash/pipeline/logstash.conf \
-v ./logstash/log/:/var/log/logstash/ \
-m 1GB \
docker.elastic.co/logstash/logstash:7.10.2

（4）验证LogStash

shell
echo -e "[#%&*^]666" >> ./logstash/log/1.log

docker exec -it logstash01 bash

curl -X GET "http://elasticsearch01:9200/_search/" \
-H 'Content-Type: application/json' \
-u 'elastic:Passw0rd' \
-d '{
  "query": {
    "match": {
      "message": "666"
    }
  }
}'

Kafka ​

（1）启动Kafka容器

shell
docker run \
-d \
--name kafka01 \
-p 127.0.0.1:9094:9094 \
--net elastic \
-e KAFKA_PROCESS_ROLES=broker,controller \
-e KAFKA_NODE_ID=1 \
-e KAFKA_CONTROLLER_QUORUM_VOTERS=1@kafka01:9093 \
-e KAFKA_LISTENERS=INTERNAL://:9092,CONTROLLER://:9093,EXTERNAL://:9094 \
-e KAFKA_ADVERTISED_LISTENERS=INTERNAL://kafka01:9092,EXTERNAL://localhost:9094 \
-e KAFKA_INTER_BROKER_LISTENER_NAME=INTERNAL \
-e KAFKA_CONTROLLER_LISTENER_NAMES=CONTROLLER \
-e KAFKA_LISTENER_SECURITY_PROTOCOL_MAP=INTERNAL:PLAINTEXT,CONTROLLER:PLAINTEXT,EXTERNAL:PLAINTEXT \
-e KAFKA_OFFSETS_TOPIC_REPLICATION_FACTOR=1 \
-m 1GB \
apache/kafka:4.1.1

为了同时支持在容器内部和宿主机外部访问Kafka，可为KAFKA_ADVERTISED_LISTENERS指定两个监听器：INTERNAL与EXTERNAL。一旦配置该参数，就不会使用默认配置（/opt/kafka/config/server.properties）了，上述其它-e参数都得加上，不然会启动报错。

单节点模式需配置KAFKA_OFFSETS_TOPIC_REPLICATION_FACTOR为1，不然会启动报错。

（2）验证Kafka

shell
# 进入Kafka容器
docker exec --workdir /opt/kafka/bin/ -it kafka01 bash

# 创建Topic
./kafka-topics.sh --bootstrap-server localhost:9092 --create --topic elastic-topic
# 使用Producer
./kafka-console-producer.sh --bootstrap-server localhost:9092 --topic elastic-topic <<< "[#%&*^]666"
# 使用Consumer
./kafka-console-consumer.sh --bootstrap-server localhost:9092 --topic elastic-topic --from-beginning

（3）集成LogStash：将Kafka数据推送到LogStash

修改logstash.conf配置文件（参见LogStash）的input内容：

input {
  kafka {
    bootstrap_servers => "kafka01:9092"
    topics => ["elastic-topic"]
    group_id => "logstash-consumer-group"
    decorate_events => true
    codec => "json"    
  }
}

完整配置如下：

shell
cat > ./logstash/config/logstash.conf << EOF
input {
  kafka {
    bootstrap_servers => "kafka01:9092"
    topics => ["elastic-topic"]
    group_id => "logstash-consumer-group"
    decorate_events => true
    codec => "json"
  }
}

output {
  # 输出ES
  elasticsearch {
    hosts => ["http://elasticsearch01:9200"]
    index => "log-%{+YYYY.MM.dd}"
    user => "elastic"
    password => "Passw0rd"
  }

  # 输出到控制台
  stdout {
    codec => rubydebug
  }  
}
EOF

重启LogStash，使用kafka-producer生成日志（json格式），在Kibana中验证日志是否写入成功。

Filebeat ​

（1）创建filebeat.yml配置文件

shell
cat > ./filebeat/config/filebeat.yml << EOF
filebeat.inputs:
- type: log
  enabled: true
  paths:
    - /var/log/filebeat/*.log

output.elasticsearch:
  hosts: 'elasticsearch01:9200'
  username: 'elastic'
  password: 'Passw0rd'
EOF

（2）启动Filebeat容器

shell
docker run \
-d \
--name filebeat01 \
--net elastic \
-v ./filebeat/config/filebeat.yml:/usr/share/filebeat/filebeat.yml:ro \
-v ./filebeat/log/:/var/log/filebeat/:ro \
-m 0.1GB \
docker.elastic.co/beats/filebeat:7.10.2

（3）验证Filebeat

shell
echo -e "[#%&*^]666" >> ./filebeat/log/1.log

docker exec -it filebeat01 bash

curl -X GET "http://elasticsearch01:9200/_search/" \
-H 'Content-Type: application/json' \
-u 'elastic:Passw0rd' \
-d '{
  "query": {
    "match": {
      "message": "666"
    }
  }
}'

（4）集成Kafka：将Filebeat数据推送到Kafka

修改logstash.yml配置文件的output内容：

output.kafka:
  hosts: ['kafka01:9092']
  topic: "elastic-topic"
  group_id => "elastic-consumer-group"
  decorate_events => true
  codec => "json"

另外，为了兼容日志含有换行符的情况，增加input的multiline配置：

filebeat.inputs:
- type: log
  enabled: true
  paths:
    - /var/log/filebeat/*.log
  multiline:
    pattern: '[#%&*^]'
    negate: true
    match: after

完整配置如下：

shell
cat > ./filebeat/config/filebeat.yml << EOF
filebeat.inputs:
- type: log
  enabled: true
  paths:
    - /var/log/filebeat/*.log
  multiline:
    pattern: '[#%&*^]'
    negate: true
    match: after

output.kafka:
  hosts: ['kafka01:9092']
  topic: "elastic-topic"
EOF

重启Filebeat，往filebeat/log/下写入任意日志，在Kafka中验证日志是否写入成功。

最后，可启动对应的ELK容器，验证常用的ELK调用链路：

  • LogStash -> ElasticSearch -> Kibana
  • Filebeat -> ElasticSearch -> Kibana
  • Filebeat -> Kafka -> LogStash -> ElasticSearch -> Kibana

Windows ​

参见官方Github页面与这篇文章 。

下载windows镜像文件（如：Windows 10 LTSC），重命名为boot.iso，放到当前目录。

shell
mkdir -p storage shared

docker run \
-it \
--name windows \
-p 127.0.0.1:8006:8006 \
-p 127.0.0.1:3389:3389/tcp \
-p 127.0.0.1:3389:3389/udp \
-v ./boot.iso:/boot.iso \
-v ./storage/:/storage/ \
-v ./shared/:/shared/ \
-e VERSION="./boot.iso" \
-e RAM_SIZE="2G" \
-e CPU_CORES="2" \
-e DISK_SIZE="32G" \
-e USERNAME="luanrz" \
-e PASSWORD="Passw0rd" \
--device=/dev/kvm \
--device=/dev/net/tun \
--cap-add NET_ADMIN \
--stop-timeout 120 \
dockurr/windows

在浏览器中访问http://127.0.0.1:8006，执行windows安装流程。安装完成后开启远程桌面访问，后续可通过Remmina等支持RDP协议的工具连接3389端口访问远程桌面。

docker-compose.yml

yaml
services:
  windows:
    image: dockurr/windows
    container_name: windows
    ports:
      - 127.0.0.1:8006:8006
      - 127.0.0.1:3389:3389/tcp
      - 127.0.0.1:3389:3389/udp
    volumes:
      - ./boot.iso:/boot.iso
      - ./storage/:/storage/
      - ./shared/:/shared/
    environment:
      VERSION: "./boot.iso"
      RAM_SIZE: "2G"
      CPU_CORES: "2"
      DISK_SIZE: "32G"
      USERNAME: "luanrz"
      PASSWORD: "Passw0rd"
    devices:
      - /dev/kvm
      - /dev/net/tun
    cap_add:
      - NET_ADMIN
    stop_grace_period: 2m

参考Nacos官方nacos-docker项目。

（1）内置数据库模式（derby）

shell
mkdir -p ./log/

docker run \
-it \
--name nacos \
-p 127.0.0.1:8114:8080 \
-p 127.0.0.1:8848:8848 \
-p 127.0.0.1:9848:9848 \
-v ./log/:/home/nacos/logs/ \
-e MODE=standalone \
-e NACOS_AUTH_TOKEN=cVykhLqhvyPjgF6r00gzJ7O73GygGYOyzescq5ovxg0= \
-e NACOS_AUTH_IDENTITY_KEY=nacos \
-e NACOS_AUTH_IDENTITY_VALUE=nacos \

  • NACOS_AUTH_TOKEN的值可以使用openssl rand -base64 32随机生成。
  • 设置-e MODE=standalone后，默认使用内置derby数据库，否则使用外置mysql数据库。

services:

    volumes:
      - ./log/:/home/nacos/logs/
    environment:
      - MODE=standalone
      - NACOS_AUTH_TOKEN=cVykhLqhvyPjgF6r00gzJ7O73GygGYOyzescq5ovxg0=
      - NACOS_AUTH_IDENTITY_KEY=nacos
      - NACOS_AUTH_IDENTITY_VALUE=nacos

（2）外置数据库模式（mysql）

shell

docker run \
-it \
--name nacos \
-p 127.0.0.1:8114:8080 \
-p 127.0.0.1:8848:8848 \
-p 127.0.0.1:9848:9848 \
--net mysql \
-v ./log/:/home/nacos/logs/ \
-e NACOS_AUTH_TOKEN=cVykhLqhvyPjgF6r00gzJ7O73GygGYOyzescq5ovxg0= \
-e NACOS_AUTH_IDENTITY_KEY=nacos \
-e NACOS_AUTH_IDENTITY_VALUE=nacos \
-e MYSQL_SERVICE_HOST=mysql \
-e MYSQL_SERVICE_DB_PARAM=allowPublicKeyRetrieval=true \
-e MYSQL_SERVICE_USER=nacos \
-e MYSQL_SERVICE_PASSWORD=nacos \
-e MYSQL_SERVICE_DB_NAME=nacos \
-e SPRING_DATASOURCE_PLATFORM=mysql \
nacos/nacos-server:v3.2.3
  • 设置--net mysql和-e MYSQL_SERVICE_HOST=mysql，寻找mysql网络下的mysql实例。
  • 设置-e MYSQL_SERVICE_DB_PARAM，避免可能出现的mysql的Public Key Retrieval is not allowed问题。
  • 设置-e SPRING_DATASOURCE_PLATFORM，避免可能出现的config_info namespace migrate pre check failed问题。

docker-compose.yml

yml
services:
  nacos:
    image: nacos/nacos-server:v3.2.3
    container_name: nacos
    ports:
      - "127.0.0.1:8114:8080"
      - "127.0.0.1:8848:8848"
      - "127.0.0.1:9848:9848"
    networks:
      - mysql
    volumes:
      - ./log/:/home/nacos/logs/
    environment:
      - NACOS_AUTH_TOKEN=cVykhLqhvyPjgF6r00gzJ7O73GygGYOyzescq5ovxg0=
      - NACOS_AUTH_IDENTITY_KEY=nacos
      - NACOS_AUTH_IDENTITY_VALUE=nacos
      - MYSQL_SERVICE_HOST=mysql
      - MYSQL_SERVICE_DB_PARAM=allowPublicKeyRetrieval=true
      - MYSQL_SERVICE_USER=nacos
      - MYSQL_SERVICE_PASSWORD=nacos
      - MYSQL_SERVICE_DB_NAME=nacos
      - SPRING_DATASOURCE_PLATFORM=mysql

networks:
  mysql:
    name: mysql
    external: true

当前模式下Nacos依赖于MySQL，首次启动Nacos时需要执行对应SQL。另外，在执行该SQL之前，需创建nacos用户和对应数据库，参考命令如下：

SQL
CREATE USER 'nacos'@'%' IDENTIFIED BY 'nacos';
CREATE DATABASE IF NOT EXISTS `nacos`;
GRANT ALL PRIVILEGES ON `nacos`.* TO 'nacos'@'%';
